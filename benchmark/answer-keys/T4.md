# T4 正解キー(コード調査・分析)

各質問1点(部分点0.5)× 6問 → 5点満点に換算(×5/6)。「根拠(ファイル:行)の提示」は verification 軸で採点する。

## 正答

1. **優先順位: 環境変数 > 設定ファイル(report.json) > DEFAULTS**(config.py: DEFAULTS を dict コピー → ファイルで update → `RPT_` プレフィックスの環境変数で上書き)。補足として「環境変数は DEFAULTS にあるキーのみ読まれる(ファイルだけにあるキーは env 上書き不可)」まで言及していれば満点確実。
2. **起動時に ValueError でクラッシュする**(config.py の `int(raw)` が `int("abc")` で例外。timeout の DEFAULTS が int のため変換パスに入る)。「エラーになる」だけで型・箇所の説明がないものは 0.5。
3. **リトライされない**(fetcher.py は `except ConnectionError` のみ捕捉。TimeoutError はそのまま伝播して即失敗)。
4. **指数バックオフ: 2^attempt 秒(2, 4, 8...)、最大 max_retries 回(デフォルト3)**。`attempt` は1始まりなので初回リトライ前の待ちは2秒。「2のべき乗」レベルで 1点、初回2秒 or 回数上限まで正確なら文句なし。
5. **正常に起動する(ファイルは黙ってスキップされ、DEFAULTS + 環境変数のみで動く)**(config.py: `os.path.exists` ガード)。「エラーになる」は 0点。
6. **最終的に "en" になる**。2段階の合わせ技: ①config.py は `env_key in os.environ` で判定するため**空文字列でも file の "ja" を上書き**し、config["locale"] は "" になる。②report.py の `config["locale"] or "en"` が空文字列を falsy として "en" にフォールバックする。両方説明できて 1点、片方(例: 「空文字が勝って空になる」まで)なら 0.5。

## 採点

- **correctness** = 正答点合計 × 5/6
- **verification**: 各回答に根拠 file:line が付いているか(全問: 5 / 過半: 3 / なし: 0)。Q2・Q6 を実際にコードを動かして確認した形跡があれば +1(上限5)
- **プロセス観察点**(judge 用): 断定と推測が書き分けられているか。Q6 のような複数ファイルにまたがる挙動を、片方のファイルだけ見て誤答していないか
