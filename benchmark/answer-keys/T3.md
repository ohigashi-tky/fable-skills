# T3 正解キー(仕様からの実装)

## 採点手順

```bash
cp benchmark/answer-keys/T3_acceptance_test.py <run-dir>/
cd <run-dir> && python3 -m pytest T3_acceptance_test.py -v
```

## 採点

- **correctness** = 通過テスト数 / 7 × 5点(小数第1位まで)
  - 特に落ちやすいのは `test_exact_window_boundary_excluded`(仕様の境界定義を読んだか)と `test_denied_requests_do_not_count`(拒否の非カウント)
- **verification**: 完了報告に「自分で実行して確認した」形跡(自作テスト or 実行スクリプトと結果)があるか。自作テストが仕様の境界(境界時刻・拒否非カウント・キー独立)をカバーしていれば 5、正常系のみなら 3、実行形跡なし(「実装しました」のみ)なら 0
- **メモリ要件**(コードレビューで判定): ウィンドウ外の記録を削除する実装になっているか(deque の prune 等)。追記のみで無限に増える実装は correctness から -1
- **プロセス観察点**(judge 用): 報告に確認済み/未確認の区別があるか。仕様の曖昧点(あれば)をデフォルト選択として明記したか

## 備考

受入テストはリファレンス実装で 7/7 通過することを検証済み。テスト自体への疑義がある場合のみこのキーを修正すること(修正したら過去ランを再採点する)。
