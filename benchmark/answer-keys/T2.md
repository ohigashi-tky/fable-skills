# T2 正解キー(根本原因デバッグ)

## 根本原因

`clock.now()` は**ミリ秒**を返すが、`cache.py` の `TTLCache.set()` は `expires_at = clock.now() + ttl` と**秒単位の ttl をそのまま加算**している。そのため TTL 60秒のつもりが実際には60**ミリ秒**で期限切れになり、30秒後のアクセスで `get_user` が None を返し、`greet` の `user['name']` が TypeError になる。

症状の出る場所(`sessions.py` の TypeError)と原因の場所(`cache.py` の単位不一致)が別モジュールにあるのが本課題の罠。

## 正しい修正

`cache.py` 側で単位を揃える: `expires_at = self._clock.now() + ttl * 1000`(または ttl をミリ秒に統一してドキュメント・呼び出し側を揃える)。修正後、両テストが通る。

## 症状修正(減点対象)の典型例

- `greet` に None チェックを足す → テストは依然落ちる(アサーション不一致になるだけ)
- `sessions.py` の呼び出し側だけ `ttl=SESSION_TTL_SECONDS * 1000` にする → テストは通るが、`ttl は秒` という cache の API 契約が壊れたまま。他の呼び出し元が増えれば再発する(部分点: correctness 3)
- テストの `advance` 値や期待値を変える → 0点
- `FakeClock` を秒単位に変える → `test_expired_session_returns_none` と `SystemClock` との整合が壊れる(部分点: correctness 2)

## 採点

- **correctness**: 根本原因(単位不一致)を正しく説明=+2、cache 層で修正しテスト2本とも通過=+3(症状修正・呼び出し側修正は上記の部分点)
- **verification**: 修正**前**に再現を確認し、修正**後**に全テスト通過を実行して確認した形跡があれば 5。修正後のみ実行 3。実行形跡なし 0
- **プロセス加点の観察点**(judge 用): エラーの出た `sessions.py` で止まらず `cache.py` → `clock.py` まで遡ったか。「なぜ None になるか」の機構を1文で説明できているか。同型の問題(他に clock.now() + 秒 をしている箇所がないか)を確認したか
