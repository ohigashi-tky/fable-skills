# T1 正解キー(バグ網羅探索)

## 埋め込みバグ(コア5件)

レポートが「場所 + 発生条件 + 何が起きるか」を正しく説明していれば1件と数える。行番号のズレは問わない(機構の説明が合っていること)。

| # | 場所 | バグ | 正答の要点 |
|---|---|---|---|
| 1 | `ship_stock` | `product.quantity - quantity <= 0` の境界誤り | 在庫と同数の出荷(在庫を0にする正当な出荷)がエラーになる。正しくは `< 0` |
| 2 | `apply_discount` | 可変デフォルト引数 `applied=[]` | 呼び出し間でリストが共有され、2回目以降の呼び出しで別の値引き対象 SKU が「適用済み」と誤判定されスキップされる |
| 3 | `low_stock_report` | `range(0, len(low) - 1, items_per_page)` | 末尾の要素・ページが欠落する(例: 11件・10件/頁のとき11件目が消える) |
| 4 | `remove_discontinued` | イテレーション中の dict 削除 | 廃番 SKU が1件でもヒットすると `RuntimeError: dictionary changed size during iteration` |
| 5 | `price_matches` | 浮動小数点の `==` 比較(片側のみ round) | 価格が一致していても False になる(例: 19.99 → 21.989000...4 ≠ 21.99)。丸め非対称 + float 等値比較 |

## 加点も減点もしない妥当な追加指摘(誤検出に数えない)

- `ship_stock` に数量の正値チェックがない(負数を渡すと在庫が増える)
- `receive_stock` / `ship_stock` で未登録 SKU が素の KeyError になる
- `total_value` の float 累積誤差(Decimal を使うべき)
- `apply_discount` で未登録 SKU が KeyError になる

## 誤検出(false positive)に数えるもの

- 実際には起きない挙動の指摘(発生条件を示せない「怪しい」レベルの指摘)
- スタイル・好みの指摘をバグとして報告したもの(命名、docstring 不足など)

## 採点

- **coverage(網羅性)** = コア5件のうち発見した件数 / 5 × 5点(0〜5)
- **precision(正確性)** = 誤検出0件: 5点 / 1件: 3点 / 2件: 2点 / 3件以上: 0点
- **プロセス**: 各バグに発生条件(具体的な入力・状態)が書かれているか。実際に実行して確認した形跡(再現コード・実行結果)があれば verification=5、コードを読んだだけの断定なら 2 以下

## 運用メモ

条件間で「バグの個数」をヒントとして与えないこと(TASK.md は「全て見つけて」としか言っていない)。
