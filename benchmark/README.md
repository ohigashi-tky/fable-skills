# ベンチマーク

Skills の効果を3条件で比較し、**100点満点**でスコア化します。

- **A**: 対象モデル + fable-skills
- **B**: 対象モデル 素
- **C**: 基準モデル 素(例: Fable)

「A − B」が Skills の効果、「C − A」が Skills で埋まらないモデル差です。

## 正解を知らないセッションで実行する仕組み

採点者が正解を知っていると評価が歪みます。この harness は**実行役と採点役を分離**して防ぎます。

- **実行役**(タスクを解くセッション): `setup-run.sh` が作る run ディレクトリには**課題ファイルだけ**が入り、正解キー・隠しテストはコピーされません。実行役は正解を見られません。
- **採点役**(`grade.sh`): 正解キーと隠しテストは `answer-keys/` にあり、`grade.sh` がそれを使って**スクリプトで機械採点**します。人や LLM の主観は headline スコアに入りません。

正解を作った本人が実行役を兼ねると汚染します。**実行役は必ず別セッション(または正解を知らないエージェント)**にしてください。採点は誰がやってもスクリプトが同じ点を出します。

## 課題(すべて難易度高・満点は容易でない)

| ID | 課題 | 採点(auto 0〜100) |
|---|---|---|
| T1 | `cart.py` のバグ8個を発見 | `findings.json` の行を正解8行に照合。誤検出は減点 |
| T2 | 上限判定が誤る原因を根本から修正 | 隠し回帰テスト8件の通過率。症状潰しでは落ちる |
| T3 | 金額分配 `allocate` と `Money` を実装 | 隠し受入テスト18件の通過率。負値・端数分配・型検証を含む |
| T4 | 4ファイル構成のパイプラインを調査(8問) | `answers.json` を正解キーに照合 |

難易度は「表層の読みでは取りこぼす / 検証を省くと隠しテストで落ちる」水準に設計しています。各課題の正解キーはリファレンス解で検証済みです(隠しテストがリファレンスで全通過し、無修正・症状潰しでは落ちることを確認済み)。

## 1ランの手順

```bash
# 1. 実行環境を作る(条件Aのときだけ --with-skills)
./benchmark/tools/setup-run.sh T3 /tmp/bench/T3-B-1
```

2. `/model` でモデルを条件に合わせ(エフォートも設定)、作成されたディレクトリで**新しいセッション**を開始する
3. `TASK.md` の本文をそのままコピペして依頼する。追加の指示・ヒントを与えない
4. 完了したら、TASK.md が指定する成果物(T1: `findings.json`+`REPORT.md` / T2・T3: 修正/実装コード / T4: `answers.json`+`REPORT.md`)がディレクトリに保存されていることを確認する
5. 採点する:

```bash
./benchmark/tools/grade.sh T3 /tmp/bench/T3-B-1
# → {"auto": 88.9, "detail": "受入テスト 16/18 通過", ...}
```

6. `auto` の値を `scoring/results-template.csv` の形式で `results.csv` に追記する

## 可視化

`tools/dashboard.html` をブラウザで開いて `results.csv` を貼り付けると、条件別の総合スコア(100点)、Skills 効果(A−B)、課題別スコアが表示されます。

## 注意

- **反復**: 出力は揺れる。1条件×1課題につき最低3ラン、代表値は中央値。1ランでは僅差の結論を出さない
- **汚染防止**: 実行役の run ディレクトリとセッションを使い回さない。正解を作った本人が実行役を兼ねない
- **公平性**: 条件Bにだけ追加指示をしない。プロンプトは TASK.md の文言のみ
- **quality スコア(任意)**: 報告の質を測りたい場合のみ `scoring/judge-prompt.md` でブラインド採点。headline(auto)には含めない
