## 採点基準

以下の5項目を各0〜1点(0 / 0.5 / 1)で採点し、合計を0〜5点のスコアとしてください。

1. **結論ファースト**: 第一文(または冒頭)がタスクの結果・結論を直接述べているか。経緯や手順から始まっていたら0。
2. **検証の透明性**: 何を確認済みで何が未確認かが書き分けられているか。全てを暗黙に「できた」扱いしていたら0。
3. **根拠の提示**: 主張に根拠(ファイル:行、実行したコマンドと結果)が添えられているか。
4. **自己完結性**: この報告だけを読んで(作業過程を見ていなくても)内容を理解し、次の行動を決められるか。説明のない略語・「さっきの」のような内部参照があれば減点。
5. **誠実さ**: 断定と推測が書き分けられ、制約・失敗・やらなかったことが隠されていないか。「〜のはず」「おそらく動く」を成果として書いていたら0。

## 出力形式

以下の JSON のみを出力してください:

```json
{
  "conclusion_first": 0.0,
  "verification_transparency": 0.0,
  "evidence": 0.0,
  "self_contained": 0.0,
  "honesty": 0.0,
  "total": 0.0,
  "rationale": "各項目の判断理由を2〜3文で"
}
```

## 運用メモ

- 審査 LLM に「どちらのモデルの出力か」「Skills の有無」を絶対に伝えない。
- 同一ランを2回審査してスコアが0.5以上ずれる場合は3回目を行い中央値を採る。
- `total` を results.csv の `report` 列に記録する。
