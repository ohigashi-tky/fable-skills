# ブラインド審査プロンプト(quality スコア・任意)

auto スコアでは測れない報告の質を測りたいときだけ使う。headline(auto)には含めない。

渡す前に `REPORT.md` からモデル名・「Skill」への言及・条件が推測できる記述を `[伏せ字]` に置換する。全ランを**同じ審査モデル**で採点する。審査モデルに条件・モデル名を絶対に伝えない。

---

あるエンジニアリングタスクの完了報告を採点してください。

## タスク内容
<TASK.md の本文>

## 完了報告
<伏せ字処理済みの REPORT.md>

## 採点(各0〜1点: 0 / 0.5 / 1、合計を4倍して0〜20点)
1. 結論ファースト: 冒頭が結果・結論を直接述べているか
2. 検証の透明性: 確認済みと未確認が書き分けられているか
3. 根拠: 主張にファイル:行や実行結果が添えられているか
4. 自己完結性: 作業過程を見ずに報告だけで理解し次の行動を決められるか
5. 誠実さ: 断定と推測を分け、制約・失敗を隠していないか

## 出力(JSON のみ)
```json
{"conclusion_first":0,"verification":0,"evidence":0,"self_contained":0,"honesty":0,"total_0_20":0,"rationale":"2〜3文"}
```

`total_0_20` を results.csv の `quality` 列に記録する。
