# Context Discipline — コンテキスト規律

コンテキストは品質の原資。無駄読みで埋めると、タスク後半の判断力・一貫性が確実に落ちる。Fable の長期タスクの安定性は、この規律の徹底による。

## 読み込みの規律

- **必要な範囲だけ読む**: 大きいファイルは Grep で行番号を特定してから offset/limit で該当部だけ Read する。200行未満のファイルのみ全文可。
- **同じファイルを2度読まない**: 編集直後の読み直し確認は不要(編集が失敗すればエラーが出る)。
- **出力の大きいコマンドは絞ってから実行**: `| head`、`--oneline`、`grep` で必要部分だけ出す。数千行のログをそのまま流さない。
- **サブエージェントに読ませる**: 「多数のファイルを読んで結論だけ欲しい」調査は、サブエージェントに投げて結論だけ受け取る。自分のコンテキストにファイル群を積まない。

## 再導出の禁止

- 会話内で既に確定した事実(ファイルの場所・設定値・ユーザーの決定)を再検索・再質問しない。
- ユーザーが既に下した決定を蒸し返さない。選択肢の再提示は再決定の強要になる。
- 迷ったときの再確認は「確定事項メモ」(下記)を見る。それでも不明なときだけ再調査する。

## 長期タスクの状態ノート

3ステップを超えるタスク、またはセッションをまたぐ可能性があるタスクでは、作業ディレクトリ外(scratchpad 等)に状態ノートを維持する:

```markdown
# タスク: <1行>
## 完了条件
- <確認可能な形で>
## 確定事項(再調査しない)
- <事実> (根拠 file:line)
- <ユーザーの決定>
## 完了済み
- [x] <ステップ> → <結果>
## 残り
- [ ] <ステップ>
## 現在の前提・注意
- <ハマりどころ、選んだデフォルト>
```

- フェーズ完了ごとに更新する。
- コンテキストが要約(compact)されても、このノートがあれば品質を落とさず再開できる。**要約後の自分への引き継ぎ書**だと思って書く。

## フェーズ分割

- 巨大タスクは「探索」「実装」「検証」でコンテキストを分ける設計にする: 探索はサブエージェントに出して結論のみ受領、実装は自分、検証はまた独立エージェントで、が理想形。
- 1フェーズの成果は上記ノートに落としてから次へ進む(頭の中の状態に依存しない)。

## アンチパターン

- 「念のため」で数千行のファイルを全文読みする
- 5分前に確認した事実をもう一度 grep する
- 長いタスクを頭の中の状態だけで進め、compact 後に前提を失って迷走する
- サブエージェントから file 全文のダンプを受け取る(結論だけ返させる)
