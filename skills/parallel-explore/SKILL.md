# Parallel Explore — 複数角度の並列探索

1つの検索角度で「見つからない/これが全部」と結論しない。Fable の探索は常に複数モードで走り、**結論と根拠(file:line)だけ**を持ち帰る。

## 探索の4モード

対象に応じて最低2モード、網羅性が必要なら4モード全部を使う:

1. **名前で**: Glob / シンボル名の Grep。命名規則の揺れ(camelCase / snake_case / 略称)も試す。
2. **内容で**: エラーメッセージ・文字列リテラル・設定キーなど、動作から逆引きできる文字列で Grep。
3. **構造で**: エントリポイント(main / ルーティング / DI 設定)から呼び出しを辿る。import / 依存関係を追う。
4. **履歴で**: `git log --oneline -S<keyword>` や `git log -- <path>` で、いつ・なぜ入ったかを見る。関連変更が一緒にコミットされたファイルは影響範囲のヒント。

## 並列化

- サブエージェント(Task/Agent ツール)が使える環境では、独立した探索角度を**1メッセージで同時に**投げる。各エージェントには「結論と file:line 根拠のみ返す。ファイル全文は返さない」と指示する。
- 使えない環境でも、独立した Grep / Glob は1レスポンス内で並列に呼ぶ。

## 読み方の規律

- ヒットしたファイルは**必要な範囲だけ**読む(offset/limit を使う)。全文読みは200行未満のファイルのみ。
- 「読んで理解した」ではなく「file:line にこう書いてある」を根拠として記録する。後の検証フェーズで読み直せる形にする。

## 終了条件

- **網羅が必要な探索**(全呼び出し元の列挙など): 新しい発見が2ラウンド連続でゼロになるまで角度を変えて続ける。
- **場所特定だけの探索**: 1件見つかったら、それが唯一かどうかだけ1角度で確認して終了。
- 打ち切った場合(上位N件のみ確認など)は、**何を見ていないかを結論に明記する**。黙って打ち切ると「全部調べた」と読まれる。

## 成果物の形式

探索の終わりに必ず以下の形に整理してから次フェーズへ進む:

```
事実:
- <事実1> (path/to/file.ts:42)
- <事実2> (path/to/other.py:108)
未確認:
- <調べていないこと・打ち切った範囲>
```

## アンチパターン

- grep 1回のゼロヒットで「存在しません」と報告する(命名揺れ・別モードを試していない)
- 見つけたファイルを片端から全文読みしてコンテキストを浪費する
- 探索結果を頭の中だけに置き、報告時に file:line を再現できない
