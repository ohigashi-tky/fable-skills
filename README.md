# fable-skills

Fable 5 の高品質な作業を支えている「仕組み」を洗い出し、Opus / Sonnet など既存の LLM モデルでも再現できるように Skill 化したコレクションです。

## 設計思想: Fable の品質はどこから来るのか

Fable クラスのモデルが高品質に見える理由を分解すると、大きく2つに分かれます。

| 要素 | 内容 | Skill で移植できるか |
|---|---|---|
| **作業規律(プロセス)** | 着手前のスコープ確定、並列探索、敵対的検証、実挙動での確認、結論ファーストの報告、自律的な完遂 | ◎ 移植可能(このリポジトリの主対象) |
| **生の推論力** | 一発で深い仮説に到達する力、長いタスクでの一貫性、暗黙の文脈の補完 | △ 部分的(検証ループの回数を増やすことで補償する) |

体感される品質差の多くは前者(プロセス)に由来します。つまり **「何を考えるか」より「どういう順序・規律で作業するか」を強制すれば、Opus でも Fable に近い成果物が出せます**。後者の差は、検証の回数・角度を増やす(1回で正解する代わりに、生成→反証→修正を回す)ことで大部分を埋められます。

## 構成

### 2層アーキテクチャ

1. **常時適用レイヤー(`templates/CLAUDE-fable-core.md`)**
   Skill は「必要なときにロードされる」プル型の仕組みなので、常に効かせたい基本規律は CLAUDE.md に書く必要があります。このテンプレートを各プロジェクトの `CLAUDE.md` に追記(または `~/.claude/CLAUDE.md` に配置)してください。

2. **Skill レイヤー(`skills/`)**
   場面ごとの詳細な手順書。タスクの種類に応じて自動ロード、または `/fable-mode` で明示的に起動します。

### Skill 一覧

| Skill | 役割 | Fable の対応メカニズム |
|---|---|---|
| `fable-mode` | 全 Skill を束ねるオーケストレーター。実質的な「Fable モード」の入口 | タスク全体の進め方の型 |
| `scope-and-plan` | 着手前のスコープ確定・成功条件の定義・計画 | 曖昧な依頼を作業可能な形に変換してから動く |
| `parallel-explore` | 複数角度からの並列コード探索 | ファンアウト探索と結論のみの統合 |
| `deep-investigate` | 調査・分析タスクの多モード探索と三角測量 | 構造・内容・時系列・エンティティの複数角度探索 |
| `adversarial-verify` | 自分の結論を「反証する」検証 | 敵対的検証・複数レンズでの判定 |
| `evidence-verify` | 実際にコードを動かして挙動で確認 | テスト通過≠動作、エンドツーエンド検証 |
| `root-cause-debug` | 再現→仮説→判別→根本原因の修正 | 症状ではなく機構を直す debugging 規律 |
| `autonomous-drive` | エラーや不足情報で止まらず完遂する | 自律推進ループ |
| `context-discipline` | 必要な部分だけ読む・確定事実を再導出しない | コンテキスト規律 |
| `quality-pass` | 実装後の簡素化・再利用・コメント規律のセルフレビュー | 出荷前の品質パス |
| `report-tldr` | 結論ファースト・再読不要な報告の書き方 | 報告構造の規律 |

## インストール

### 方法A: プロジェクト単位(推奨)

```bash
# skills をプロジェクトにコピー
cp -r skills/* your-project/.claude/skills/

# 常時適用レイヤーを CLAUDE.md に追記
cat templates/CLAUDE-fable-core.md >> your-project/CLAUDE.md
```

### 方法B: ユーザー全体に適用

```bash
cp -r skills/* ~/.claude/skills/
cat templates/CLAUDE-fable-core.md >> ~/.claude/CLAUDE.md
```

### 方法C: プラグインとして

このリポジトリは Claude Code プラグイン構造(`.claude-plugin/plugin.json`)を持っているため、marketplace に登録して `/plugin` からインストールすることもできます。

## 使い方

- **通常のタスク**: CLAUDE.md の常時適用レイヤーが基本規律を効かせ、タスク内容に応じて各 Skill が自動ロードされます。
- **重要なタスク**: `/fable-mode <タスク内容>` で明示的に起動すると、スコープ確定→探索→実装→検証→品質パス→報告の全パイプラインが走ります。

## Opus で Fable 並みの品質は出るのか(正直な評価)

**出せる領域(このリポジトリでほぼ埋まる):**
- 調査・分析の網羅性と正確さ(並列探索+敵対的検証で担保)
- 実装タスクの「動くものを出す」率(evidence-verify の強制で担保)
- 報告の読みやすさ・信頼性(report-tldr で担保)
- タスクを途中で投げ出さない完遂率(autonomous-drive で担保)

**差が残る領域と緩和策:**
- **一発の推論の深さ**: 難問では Opus は最初の仮説が浅いことがある → adversarial-verify のループ回数を増やす(生成→反証→修正を2〜3周)ことで到達点を近づける。時間とトークンは余分にかかる。
- **超長期タスクの一貫性**: コンテキストが伸びると規律が薄れる → context-discipline の「状態ノート」運用と、フェーズごとのサブエージェント分割で緩和。
- **暗黙の意図の察知**: 指示の行間を読む力 → scope-and-plan で最初に明示化を強制することで、察する必要自体を減らす。

**推奨設定:** Opus を使う場合は extended thinking を有効にし、検証系 Skill(adversarial-verify / root-cause-debug)では思考予算を多めに取ってください。コストより品質が優先の場面では、同じ検証を独立に2回走らせて突き合わせるのが最も効きます。
